# axis:ppt3 — 라이트 그라디언트 카드 덱 (강의·발표용, 장수 자유)

ppt1·ppt2 가 "데이터 한 장 → 2장 현황 보고"라면, ppt3 는 **내용을 여러 장으로 풀어 설명하는 강의·발표 덱**이다.
결과물은 HTML 1개(+ PDF). 브라우저에서 바로 발표하고, `E` 로 글자를 고치고, 도식 장에서는 박스를 끌어 옮기고, `Ctrl+P` 로 PDF 를 뽑는다.

이 스킬은 `template.html`(견본 12장)의 **CSS·효과·편집 엔진을 그대로 쓰고, 장(section)만 새로 쓴다.**
장은 조각 파일에 쓰고 `tools/build.py` 로 조립한다. 규칙과 컴포넌트 규격은 `style.md` 에 있다.

편집 엔진은 [RDDcat/maro-ppt](https://github.com/RDDcat/maro-ppt)(MIT) 의 인라인 편집·도식 편집기(DG)·저장 서버·발표용 내보내기를 이 덱 구조에 맞게 옮겨 넣은 것이다.

## 0. 먼저 읽을 것

| 파일 | 내용 |
|---|---|
| `template.html` | 견본 덱 12장. 타이틀·두 카드·단계+일러스트·차트·통계 타일·플로우·세 칸·질문·네 칸·도식 장이 한 번씩 있다. 효과·편집·인쇄 CSS 포함 |
| `style.md` | 디자인 토큰, 1600×900 격자, 컴포넌트 규격, 장 유형별 권장 구성, 확정된 규칙 |
| `tools/build.py` | 조각 파일(장들) + 차트 JS → 템플릿에 끼워 완성 HTML 생성. 차트 키·도식 id 검사 |
| `tools/export.py` | 헤드리스 Chrome 으로 `check`(런타임 오류)·`overflow`(넘침 검출)·`shot`(장별 스크린샷)·`pdf` |
| `tools/serve.py` | 저장 서버 — 브라우저에서 고친 글자·도식이 즉시 원본 HTML 에 저장. 덱 옆의 사진·글꼴도 읽기 전용으로 내준다 |
| `tools/retrofit.py` | 편집 엔진 이식 — 편집 기능이 없는 기존 덱에 템플릿의 편집 엔진을 끼워 새 파일로 낸다 (6절) |
| `tools/README.md` | 편집 키·도식 편집·저장·발표용 내보내기·배율 설명 (완성본과 함께 전달) |

## 1. 내용 정리 → 장 구성

1. 원문(코스·문서·메모)을 끝까지 읽고 **장 하나에 메시지 하나**로 쪼갠다. 25장 안팎이면 한 번 발표 분량(50~75분)이다.
2. 각 장은 `킥커(소제목) → 제목(핵심구 `<span class="g">` 강조) → 본문 블록 → 밴드(한 줄 결론)` 순서다. 밴드는 "그래서 무엇"을 적는다.
3. 장 유형을 고른다 (`style.md` 3절):
   - **타이틀**(`s-title`) · **두 칸 카드**(`two`) · **단계 + 일러스트/차트**(`two w` + `.steps`) · **세 칸**(`three`) · **네 칸**(`four`)
   - **플로우**(`.flow`, 3단계 →) · **통계 타일**(`.stat`, 큰 숫자 3개 + 차트) · **질문**(`s-ask`, 가운데 정렬) · **구조 도식**(`.dg`, 박스+화살표)
4. 숫자가 있는 장에만 차트를 넣는다. 종류는 Chart.js 공식 샘플(막대·가로 막대·도넛·선)에서 고른다.
5. 상단 메뉴는 4~6개 구간으로 나눈다(`--menu "시작=1,역사=9,…"`).

## 2. 만들기

1. 작업 폴더에 `{이름}-slides.html`(장 조각)과 필요하면 `{이름}-charts.js`(차트 함수)를 쓴다.
   - 조각은 `<section class="slide …">…</section>` 만 나열한다. 머리말·스크립트 없음.
   - 등장 순서는 `class="… r" style="--i:N"` 으로 준다(0부터, 0.11초 간격).
   - 도식 박스 `id` 는 덱 전체에서 유일하게(`w1-a`, `w1-b` …).
   - 차트는 `<div class="chart r"><h4><span>제목</span> <small>출처</small></h4><div class="cv"><canvas data-chart="키"></canvas></div></div>` 와 charts.js 의 `키(c){return new Chart(c,{…})}` 쌍으로.
2. 조립:
   ```bash
   python "${CLAUDE_SKILL_DIR}/tools/build.py" --slides "w1-slides.html" --charts "w1-charts.js" \
     --title "1주차 — AI란 무엇인가" --desc "…" --logo "AX:IS" --logo-sub "AI 기초 4주 · 1주차" \
     --menu "시작=1,정의=4,역사=10,데이터=15,정리=24" --out "1주차_AI란무엇인가.html"
   ```
3. 바꾸면 안 되는 것: `:root` 토큰, 1600×900 스테이지, `.r` 등장 규칙, 인쇄 CSS, `data-editor` 블록 4개(편집 CSS·도구·편집 스크립트 2개), 도식 보기(DGV)·배율 스크립트, `beforeprint`.
4. 스크립트가 만드는 요소(`.dg-wire`·`.dg-fit`·`.dg-grip`·인라인 transform)를 조각에 직접 쓰지 않는다. 편집 저장 시 `html()` 이 걷어내고 다시 만든다.

## 3. 검증 — 만들고 나서 반드시

```bash
python "${CLAUDE_SKILL_DIR}/tools/export.py" check    "덱.html"     # node --check · 모든 장을 열어 런타임 오류 0 · 차트 생성 수 · 도식 화살표 수
python "${CLAUDE_SKILL_DIR}/tools/export.py" overflow "덱.html"     # 밴드 하단 한계(840px)·좌우 밖으로 넘친 요소 목록. OK 가 나와야 한다
python "${CLAUDE_SKILL_DIR}/tools/export.py" shot     "덱.html" --slides 1,5,12   # 의심 장 스크린샷 (전 장은 --slides 생략)
```
- `overflow` 가 요소를 찍으면 그 장의 글자를 줄이거나 카드 수를 줄인다. 글자 크기를 전역으로 줄이지 않는다.
- 스크린샷은 **반드시 눈으로 본다**: 카드 안 줄바꿈, 밴드가 두 줄이 되지 않는지, 도식 화살표 라벨 겹침, 차트 범례 잘림.
- GPU 를 끈 헤드리스는 3D 큐브·캔버스가 비어 보인다. `export.py` 는 GPU 를 켠다.

## 4. PDF

```bash
python "${CLAUDE_SKILL_DIR}/tools/export.py" pdf "덱.html"       # 같은 이름의 .pdf, 장 수만큼 쪽, 1600×900
```
인쇄 CSS 가 슬라이드 1장 = 1쪽으로 잡고 배경 효과·내비·편집 도구를 뺀다. `beforeprint` 에서 모든 차트를 최종값으로 만들고 도식을 그린다.

## 5. 전달

- 저장 서버로 열어 주면 편집이 즉시 파일에 저장된다: `python "${CLAUDE_SKILL_DIR}/tools/serve.py" --open "덱.html"`
- 완성 안내에 적을 것: 파일 경로, 키(`←→` 이동 · `F` 전체 화면 · `E` 편집 · `Ctrl+S` 저장 · `[` `]` 배율 · 도식 장에서 편집 켜면 박스 끌기 · 마지막 장 `[편집 기능 삭제]`), Chart.js·Pretendard 폰트는 CDN 이라 인터넷 필요.
- 장별 한 줄 요약표를 같이 보여 준다.

## 6. 기존 덱을 고칠 때 — 편집 엔진부터 확인

장을 덧붙이거나 고치기 전에 **그 덱에 편집 엔진이 있는지 먼저 본다.** 편집 엔진이 들어오기 전에 만든 덱이나,
손으로 고치다 엔진이 빠진 덱이 있다. 편집 기능 없는 덱을 사용자에게 넘기지 않는다.

```bash
grep -c 'id="edit"' "덱.html"     # 0 이면 편집 엔진이 없다 → 이식부터
python "${CLAUDE_SKILL_DIR}/tools/retrofit.py" "덱.html" --out "덱_v2.html"
python "${CLAUDE_SKILL_DIR}/tools/export.py" check "덱_v2.html"   # data-editor 4 · id=edit 1 · id=final 1 · ERRS 비어 있음 · EDIT=function
```

- `retrofit.py` 는 장·CSS·차트·덱 고유 스크립트를 그대로 두고, 템플릿의 편집 CSS·하단 도구·편집 스크립트 2개(`data-editor`)와
  배율·도식 보기·인쇄 CSS/스크립트(편집 기능 삭제 뒤에도 남는 것)를 붙인다.
  덱 제어 스크립트는 고리만 고친다: `go()` 끝 `deck:slide` 이벤트, keydown·빈 곳 클릭·스와이프의 "편집 중이면 무시", `.stage` 의 `--zoom`, 힌트 문구.
  고리 자리를 못 찾으면 멈춘다 — 그때는 덱 구조를 읽고 손으로 맞춘다.
- 원본은 덮어쓰지 않고 `_v2` 같은 새 이름으로 낸다. 사용자가 원본을 열어 두고 있을 수 있다.
- 이미 엔진이 있는 덱이면 이식하지 않고 바로 고친다.

**사용자가 브라우저에서 고친 것을 묻지 않는다** (maro-ppt 6-0)

| 원인 | 할 일 |
|---|---|
| 편집이 브라우저에만 있고 파일에 없다 | 덱은 저장 서버로 연다(5절). file:// 로 열려 있던 덱이면 고치기 전에 `Ctrl+S` 를 한 번 부탁한다 |
| 예전 조각·기억으로 덱을 **다시 빌드**한다 | 하지 않는다. 디스크의 현재 파일을 새로 읽고 **그 장만 부분 치환**한다. 바꿀 문자열이 정확히 한 번 있는지 확인하고, 없으면 사용자가 이미 고친 것이니 다시 읽고 사용자 문장 기준으로 맞춘다 |
| 에이전트 수정 **전에** 열어 둔 탭에서 계속 고친다 | 저장 서버로 연 탭은 알아서 새로고침한다. 새 탭을 또 띄우지 않는다. file:// 탭이면 새로고침을 부탁한다 |

**새 부품을 넣을 때 (편집과 엮이는 것)**

- 글자는 자동으로 편집 대상이 된다 — 장 안에서 맨 글자(텍스트 노드)를 직접 가진 요소는 선택자 목록에 없어도 잡힌다.
  빼려면 `data-noedit`, 맨 글자가 없는데 넣으려면 `data-txt`. SVG 글자는 편집 중 더블클릭.
- 스크립트가 실행 중에 만드는 요소(사진 확대창·툴팁 등)는 **스크립트로 만들고 `data-runtime` 을 붙인다.** 저장(`html()`)할 때 걷힌다.
  마크업에 미리 써 두면 열린 상태 그대로 파일에 저장될 수 있다.
- 클릭으로 무언가 여는 부품은 편집 중(`body.editing`)에는 열지 않는다 — 그 안의 글자를 고칠 수 있어야 한다.
- 사용자가 준 사진은 덱과 같은 폴더에 두고 상대 경로로 부른다. 저장 서버는 사진·글꼴을 읽기 전용으로 내주고(쓰기는 `.html` 만),
  `export.py` 는 원본 폴더를 `<base>` 로 걸어 사본에서도 사진이 보인다.

## 7. 확정된 규칙 (사용자 피드백에서 나온 것 — 어기지 않는다)

1. **디자인 레퍼런스**: 연한 바탕 · 흰 둥근 카드 · 블루→바이올렛→핑크 그라디언트 강조 · 상단 내비게이션 바 · 통계 타일과 게이지 차트. Envato 레퍼런스의 글로잉 큐브·회로·파티클은 배경 효과로만 쓴다.
2. **폰트는 Pretendard**(눈누 variable-694, jsdelivr), `word-break:keep-all` 로 단어 단위 줄바꿈. 글자가 단어 중간에서 끊기면 안 된다.
3. **마우스 반응**: 배경 큐브·블롭이 커서 반대로 이동, 카드는 3D 틸트 + 그라디언트 테두리, 커서를 따라가는 스포트라이트와 파티클 연결선. 효과 코드는 손대지 않는다.
4. **그림은 인라인 SVG** 로 그린다(공용 그라디언트 `#gA #gV #gSoft #gLine #gGray #gGreen #gRed`, 필터 `#glow #shadow`). 장식용 외부 이미지를 넣지 않는다(사용자가 준 스크린샷·사진은 예외 — 6절).
5. **차트는 숫자가 있는 장에만**, Chart.js 공식 샘플 종류만. 색은 `#3b82f6→#8b5cf6` 그라디언트 + 회색 `#c9d0dd`.
6. **슬라이드에 조작 안내 문구를 쓰지 않는다**("마우스를 올리면…", "클릭하세요"). 하단 힌트 줄이 그 역할을 한다.
7. 11장 축약본을 만들 때 **메뉴를 섹션 수에 맞춰 다시 짠다**(시작·격차·숫자·생산자·활동 식). 메뉴 항목 ≤ 6.
8. 밴드(결론 줄)는 **한 줄**. 두 줄이 되면 문장을 줄인다.
9. 출처가 있는 숫자는 `<small>` 또는 `.src` 에 출처를 적는다. 추정치는 "추정"이라고 쓴다.
10. 편집 기능은 발표 파일에 남겨 두고, 발표용 사본은 마지막 장의 `[편집 기능 삭제]` 로 따로 만든다.
11. **기존 덱을 고치거나 장을 덧붙일 때도 이 스킬을 따른다.** 편집 엔진이 없는 덱은 `retrofit.py` 로 먼저 이식하고(6절), 편집 기능 없는 덱을 넘기지 않는다.
    확인하지 않은 키 안내("E 로 고칠 수 있다")를 하지 않는다 — `export.py check` 의 `EDIT=function` 을 보고 말한다.

## 8. 체크리스트

```
□ 장마다 킥커·제목(강조구)·밴드 한 줄 · 밴드가 두 줄이 아님
□ data-chart 키마다 charts 함수 있음 (build.py 가 검사) · 차트는 숫자 장에만
□ 도식 박스 id 유일 · 화살표 from/to 존재 (build.py 가 검사)
□ export.py check: node --check OK · ERRS= 비어 있음 · CHARTS_MADE = 캔버스 수
□ export.py overflow: OK
□ 스크린샷 눈 검증 (의심 장 전부)
□ data-editor 블록 4개 · id="edit" · id="final" 존재 (기존 덱이었으면 retrofit 으로 이식했는가)
□ 새로 넣은 부품의 글자도 편집 중에 고쳐지는가 · 실행 중에 만드는 요소에 data-runtime
□ PDF 쪽 수 = 장 수
```
